# eglantineps5-main.md: the core patches EglantinePS5 `main` added after `v2`'s fork point, judged for `v2`. Writer: its triage agent (2026-11-10)

EglantinePS5 `origin/main` (`095df4e`, 2026-11-10) carries 49 core patches that the baseline `44d0d9d` does not: `tools/eglantine-patches/0018` to `0071` (0060, 0065-0067 and 0070 are absent: reserved for open pull requests #93 and the storage-tracking branch). Each row says whether `v2`'s in-tree core (`v2-current`, tree of `core-v2`'s index at step 41) already has the change, takes it as written, or needs it adapted to `v2`'s own work.

## Method

- Chain: `/Volumes/Hangar/ps5/scratch/triage-20261110/ps5-patches/chain`, branch `ps5-main`: `horizon-v2`'s `ed74d995de` (pin + patches 0001-0017) plus one commit per patch, applied with `git apply --index` as `tools/apply-eglantine-patches.sh` does (`git -C Eglantine apply`). Patch `00NN` is the tag `p00NN` (`git show p0063`, `git diff p0063^ p0063`).
- **Applies to v2**: `git merge-tree --write-tree --merge-base=p00NN^ v2-current p00NN`. `clean` means the patch alone merges into `v2`'s core without conflict; otherwise the conflict files are listed. A patch that builds on an earlier patch of the chain that `v2` lacks inherits that patch's conflicts (named as `needs 00NN`).
- **Anchors**: files that `tools/prepare-vulkan-port.py` (`vkport:`) or `headless/CMakeLists.txt` / `headless/*.cmake` (`cmake:`) rewrite at build time. After porting such a patch, run `prepare-vulkan-port.py --report`.
- **Lowering evidence**: EglantinePS5's own tests for 0040-0049, 0068 and 0069 (`ampere_call_noinc_loop_exit.cpp`, `ampere_pokopia_compute.cpp`, `ampere_ocarina_gameplay.cpp`, as of 0071) were compiled against `v2-current`'s Ampere headers with a Catch2 shim (`/Volumes/Hangar/ps5/scratch/triage-20261110/ps5-patches/harness/run.sh v2-current`): 19 cases, 116 assertions pass, 27 fail and one case stops early (all 154 assertions pass on `p0071`). The failures are named in the rows.
- Measurements are EglantinePS5's own, from its pull requests and `docs/` (`BANANZA-INGOT-ISLE.md`, `FASTMEM64-WINDOW.md`, `GRAPHICS-BACKPORT.md`, `LICHII-PORTS.md`, `MKW-MEMORY-LEAK.md`), on its maintainer's console. None was repeated on ours.
- The graphics stack's numbers (#56-#60: Bananza gate 15.50 to 16.07 FPS, Mario Kart World 29.0 to 33.6 FPS in one run) include port-side work `v2` does not have (`prepare-vulkan-port.py` grew by 728 lines in #57-#59), so they are an upper bound for the core patches 0025-0033 alone.

## The fastmem window (0020, 0021 and the port side of #49, #61-#64, #73)

What it is: a 2^38-byte fastmem arena for 64-bit games (`src/host_memory.cpp`, `Window64`), empty until a JIT access faults; the fault handler aliases the guest's 2 MiB slot (or a 16 KiB piece) there and the access repeats. Sites it cannot serve are demoted to the page-table path and saved per title.
