PS5 facts used below: RADV (Mesa 26.2.0) reports `minStorageBufferOffsetAlignment` 4 and supports descriptor aliasing (only Qualcomm sets `has_broken_descriptor_aliasing`); `needs_demote_reorder` is off on RADV; CPU accuracy defaults to Auto (`headless/main.cpp:846`), which forces `Unsafe_IgnoreGlobalMonitor` (`arm_dynarmic_64.cpp`); compute barriers are on by default (`::Eden::DevVulkan::compute_barriers = true`, `headless/dev_vulkan.h:29`); asserts are soft and the Switch 2 and `nx2:` services are auto-stubbed. A fix gated on `VK_DRIVER_ID_AMD_PROPRIETARY`, AMDVLK or NVIDIA does nothing on the PS5.

## Port order and dependencies

1. **K1** (or:98e0cd7161, SPIR-V files only). Applies.
2. **K4** (dj-pr#614 01783ceb29, `src/shader_recompiler` plus one line in `src/tests/CMakeLists.txt`). Applies on top of K1. It edits `spirv_emit_context.cpp`'s global-memory functions, so it goes before O1.
3. **O1** (li:18cfe85563). `emit_spirv_memory.cpp` and `vk_scheduler.cpp` as written; `spirv_emit_context.cpp` adapted on top of K4 to the pin's `DefineGlobalMemoryFunctions(const Info&)`; `WaitForIdle` in `vk_rasterizer.cpp` by hand (a pipeline barrier to `ALL_COMMANDS` plus a memory barrier instead of the `TOP_OF_PIPE` event). Run `tools/prepare-vulkan-port.py` afterwards to confirm its anchors in `vk_rasterizer.cpp` and `vk_scheduler.cpp` still match.
4. **O6** (or:a12ade280b). Applies.
5. **O5** (or:e92be12b48, the `SurfaceBoundBuffer` override only).
6. **K2** (li:f6a8f51324's `BlitConstantsPass` hunk, then li:546cb67825's phi extension), with a test written for the pin.
7. **K3** (or:98e0cd7161's geometry part). It shares `lower_to_maxwell.h` with v2's uncommitted Pokopia CALL fix: land that fix first.
8. **O3** (or:b2c6b4b7cd). It raises `IR::NUM_REGS` to 768 and every later OoT lowering assumes it; then its followers li#100 (or:e364174bd0), or:71add15abd and or:9cd48205be with or:fad602fc5f. li-pr#149's ae7037b650 and li-pr#189 can then be adapted to orchid's `register_pressure.h`.
9. **O2** (TLD4.DC from or:d1607c1ade, compared with dj-pr#614 f918505146 and li#112). Orchid wrote it after O3, so port it after O3.
10. **O4**, one work package: take the forms in the order the console's rejection log counts them.
11. **li:c9bdbaa38e**, optional.

Every shader-changing step bumps the Vulkan `CACHE_VERSION` (port-log precedent: li#150 set GL 24, VK 28); one bump per batch is enough. Each step goes on `horizon-v2` first, then into `v2` before the Qt removal ([PLAN.md](../../PLAN.md) line 46). O7 is a user mod, not a core change.

Blockers. None of steps 1-6 is blocked. Steps 7-10 are hand-ports: the forks' `lower_to_maxwell.h` hunks do not apply to the pin's copy. O3 changes `IR::NUM_REGS`. OoT and Kirby have no console run on `v2` yet ([console-test.md](../console-test.md) lines 59-60 are empty), so O4's priorities, and the need for K5 and K9, wait for the first console log of each game.
